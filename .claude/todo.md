- [x] `/api` authentication for panel and external callers — **Decided 2026-09-30:** one project middleware, `app/middleware/api_auth_middleware.ts`, registered as `apiAuth` and applied per group: `.use(middleware.apiAuth({ external: true | false }))`. See [guide.md](guide.md) §11.
  - With a `Bearer` header, a panel-only group (`external: false`) answers 401, and an external group authenticates with the `api` token guard **only**.
  - Without one, both authenticate with the `web` session guard.
  - `config/shield.ts` skips CSRF only for `/api/*` requests carrying `Bearer`, plus `POST /api/login`. That endpoint returns a token and never creates a session; the panel keeps logging in at `/login`.

Reversing the order does not help. The full comparison is in guide §11.

- [x] Error handling — **Decided 2026-09-30:** all error-to-response mapping lives in `app/exceptions/handler.ts`, and controllers have no `try/catch`.

  - Rules: never catch inside a transaction without rethrowing, or Lucid commits the partial writes, which is task-list's "empty catch" bug. `try/catch` is only for translating an error, e.g. Postgres `23505` → "Code already exists", and it rethrows.
